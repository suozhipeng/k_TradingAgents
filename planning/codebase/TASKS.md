> 本文档中的 Phase 0-11 是长期 `Product Roadmap Stage`，用于描述产品

> 与实际完成状态以 `docs/ASTOCK_CURRENT_STATUS.md` 为准。

## 规划依据
- 以 `planning/codebase/ASTOCK_RESOURCE_PLAN.md` 为总纲。
- 以 `planning/a-stock-resource/` 里的图片作为事实依据。
- 当前源码基线仍是 `TradingAgents` 的通用多 Agent 金融研究/交易决策框架。
- 当前目标态不是“泛化交易助手”，而是 **A 股投研与交易闭环系统**。

## 当前基线 vs 目标态

### 当前基线（来自现有仓库，Phase 0–11 交付后）
- 基于 LangGraph 的多 Agent 编排
- 主要链路是 Analyst → Bull/Bear → Research Manager → Advisory Chain (ResearchConclusion → TraderProposal → RiskDecision → PortfolioDecision，Phase 9)
- 通用数据层以 yfinance 为主，A 股五层数据路由已独立实现
- 输出包括研究报告、advisory 合约和可选的执行路径（回测/模拟盘/QMT）
- 已增加 A 股五层数据路由、统一接口和 AStockAnalyst
- 已增加包含 Phase 9 advisory chain 的 research runtime，advisory 输出固定为 `actionable=false`
- 已增加 A 股 CLI 报告、Streamlit 只读 UI 和 legacy 多市场 viewer
- 已增加回测引擎和模拟盘引擎（Phase 10）
- 已增加 QMT 桥接和受控执行层（Phase 11），默认 safety mode
- 当前 A 股所有 advisory 和执行输出保持 `actionable=false`，除非 safety mode 下人工确认

### 目标态（来自 `planning/a-stock-resource/`）
- 面向 **A 股投研分析 + 交易闭环**
- 数据源围绕 `mootdx / 腾讯财经 / akshare / iwencai / 巨潮 / QMT`
- 能力按五层组织：行情 / 研报 / 新闻 / 基础数据 / 公告
- 原始材料强调 **13 个接口**；工程实现统一拆分为 **18 个能力点**
- 落地路径明确为：**回测验证 → 模拟盘试跑 → 实盘出击**
- 实盘链路包含 **QMT 桥接、安全模式、人工确认、ATR 止损 / 跟踪止盈**

## 总目标
把当前 TradingAgents 从“通用多 Agent 金融研究/交易建议框架”二次开发成：

**A 股投研与交易闭环系统**

强调：
- 以 A 股数据源为核心，而不是只替换 ticker
- 以五层数据能力组织系统，而不是只扩几个工具函数
- 以回测 / 模拟盘 / 实盘三阶段推进，而不是直接跳到下单
- 以风控和人工确认约束实盘能力，而不是默认自动交易
- 以统一 Skill / 接口封装支撑上层 Agent、CLI、Web UI 和后续 API

## 拆解原则
- 保留现有 LangGraph 多 Agent 骨架，避免无谓推倒重来
- 先改数据层与接口层，再改 Agent 角色和输出层
- 先做可验证的回测/模拟，再谈实盘自动化
- 当前事实与目标态分开写，不把图片中的目标表述成仓库已完成事实
- 所有实盘相关能力默认附带风险提示、人工确认和可关闭开关

## Phase 0：边界定义与总纲固化

**目标：** 把“这到底是个什么系统”写清楚，避免后续设计左右摇摆。

### 任务 0.1：固化产品定位
- 明确项目主定位：`TradingAgents-Astock`
- 明确一句话定义：A 股投研与交易闭环系统
- 明确不是单纯“看盘工具”，也不是默认自动实盘机器人
- 把“7 位分析师 / 多空辩论 / 风控决策 / 基于 TradingAgents 深度改造”写入总纲

### 任务 0.2：固化五层能力模型
- 在 planning 中统一使用五层命名：
  - 行情层
  - 研报层
  - 新闻层
  - 基础数据层
  - 公告层
- 所有后续模块、页面、接口、Agent 设计都按这五层对齐

### 任务 0.3：固化三阶段落地路线
- 把项目路线固定为：
  - 回测验证
  - 模拟盘试跑
  - 实盘出击
- 明确每个阶段的成功条件、风险边界和退出条件

### 任务 0.4：固化合规与免责声明
- 在规划文档中固定保留：
  - 仅作学习/研究记录
  - 不构成投资建议
  - 股市有风险，投资需谨慎
- 明确文档里的“实盘能力”是系统能力范围，不等于默认启用

## Phase 4：A 股领域模型与 Agent 重构

**目标：** 把当前通用金融 Agent 体系改造成更贴近图片目标态的 A 股分析/决策体系。

### 任务 4.1：保留现有五阶段骨架
- 保留现有大框架：
  - Analyst Team
  - Research Team
  - Trader
  - Risk Management Team
  - Portfolio Manager
- 在 planning 中说明：先演化，不盲目推翻

### 任务 4.2：重定义分析师职责
- 围绕五层数据能力重写分析师输入与职责：
  - 行情分析师
  - 研报分析师
  - 新闻分析师
  - 基础数据分析师
  - 公告分析师
- 明确每类分析师调用哪些接口层

### 任务 4.3：重定义研究阶段
- 保留多空辩论这一项目特征
- 但把辩论素材切换到 A 股五层数据
- 明确辩论输出不是空泛观点，而是可落到策略评分和风险约束的结构化中间结果

### 任务 4.4：重定义 Trader / Decision 层
- 使其从“泛化交易提案”演化成 A 股策略执行前的信号汇总层
- 规划中要明确：
  - 何时只给建议
  - 何时允许进入模拟盘
  - 何时允许进入实盘确认

### 任务 4.5：重定义 Risk / Portfolio 层
- 让风控层显式吸收图片中的规则：
  - 安全模式
  - 人工确认

## 关键结论
把本项目改造成 A 股方向，最适合的思路不是：
- 在现有通用研究框架上零散加几个 A 股工具
- 或把“看盘”和“实盘”混成一个不受控流程

而是：
