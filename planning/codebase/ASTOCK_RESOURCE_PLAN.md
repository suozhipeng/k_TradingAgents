## 8. 数据源 & QMT 实盘交易

图片 7 给出一个很明确的双数据源/双系统结构：

### 8.1 akshare
- 作为腾讯行情源
- 历史数据：SQLite 本地缓存，按 code+date 去重
- 实时行情：腾讯 `qt.gtimg.cn` API，延迟约 3 秒
- 股票名称：含中文名，质量好
- 优势：无需外部依赖，非交易时间可用

### 8.2 QMT（国金证券券商源）
- 历史数据：`xtdata.get_local_data` 本地高速读取
- 实时行情：`xtdata.get_full_tick` 毫秒级低延迟
- 实盘交易：`xtrader` 下单到交易所
- 优势：数据精准，支持实盘下单，交易时段可用

### 8.3 QMT 桥接架构
图片里还写明：

- Python 3.12 主系统
- `QmtSource`（HTTP 客户端）
- HTTP 端口 `58609`
- Python 3.6.8 QMT 桥接（`qmt_bridge.py`）
- `xtdata` → Mini QMT（`:58610`）
- `xttrader` → 全功能 QMT（国金证券）
- 对接上海/深圳证券交易所
- 交易模式：安全模式（人工确认）+ 自动交易
- 风控：ATR 动态止损 10% + 跟踪止盈 3% 激活

### 8.4 规划含义
这部分说明后续规划必须明确区分：

- 数据接入
- 桥接层
- 下单层
- 人工确认模式
- 自动模式
- 风控规则
