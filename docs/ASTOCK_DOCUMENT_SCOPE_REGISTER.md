# A 股文档范围登记

| 更新时间：2026-06-23 |

本文记录当前需求文档包的纳入范围、暂不纳入范围和后续触发条件。当前文档只从核心功能实现视角展开，不扩展为完整企业级运营、法务、安全、隐私、SLA 或权限体系。

## 1. 当前纳入范围

当前 docs 面向“核心功能的生产级开发准备”，纳入以下文档边界：

- 产品需求、总需求、技术拆解、Backlog。
- 专业金融缺口、代码边界、WebUI 重构设计。
- API 契约、数据字典与血缘、测试验收、实盘运行手册。
- 风险披露与合规边界、产品指标与 Ops、需求追踪矩阵。
- 核心功能运行所需的部署与环境、数据源使用边界、模型治理、发布兼容和 UI 规范。
- Phase 归档、Hermes/Codex/DeepSeek 协作流程和 live provider 验证溯源。

## 2. 暂不纳入范围

以下模块当前只登记，不展开成需求、设计、开发任务或验收门槛：

| 模块 | 当前处理 | 原因 | 重新纳入触发条件 |
|---|---|---|---|
| 安全与隐私文档 | 仅登记 | 当前阶段只做核心功能实现，不展开密钥、个人数据、账号、日志脱敏和隐私保留策略 | 明确准备对外托管、多人协作、真实账户接入或客户交付 |
| SLA 与故障分级 | 仅登记 | 当前阶段只做核心功能实现，不定义服务可用性承诺、故障等级和响应时效 | 明确需要生产运维承诺、客户合同或值班体系 |
| 用户角色/RBAC | 仅登记 | 当前阶段不设计账号体系、角色权限和访问控制矩阵 | 明确进入多用户、团队协作、企业部署或合规权限管理 |

## 3. 不允许隐式引入

在上述模块重新纳入前，后续 phase 不得隐式引入以下内容：

- 不得新增用户角色、角色名称、权限矩阵或 RBAC 规则。
- 不得承诺 SLA、可用性百分比、故障响应时效或赔付义务。
- 不得把密钥管理、隐私合规、个人信息处理扩展为正式实现任务。
- 不得把“安全边界”误扩展为完整安全与隐私合规文档；当前安全边界只用于交易执行和 AI advisory 约束。
- 不得把部署、发布、数据源使用边界扩展为企业级 DevOps、合同 SLA 或法务审查体系。

当前仍允许保留以下非完整模块能力：

## 5. 后续更新规则

- 如果用户明确要求重新纳入任一暂不纳入模块，先更新本文，再新增对应需求文档。
- 如果代码开发中需要相关能力，只能记录为外部依赖或未来触发条件，不进入当前 phase 验收。
- 如果某个文档不可避免提到这些模块，必须标注“暂不展开”。
