# A 股产品指标与运维需求

| 更新时间：2026-06-23 |

本文定义 TradingAgents-Astock 的产品成功指标、运行指标、告警需求和运维闭环。它用于补齐 PRD 中“如何判断产品可用、可靠、可运营”的问题。

## 1. 指标分层

| 指标层 | 目标 | 示例 |
|---|---|---|
| 产品价值指标 | 判断用户是否完成关键工作流 | 研究报告完成率、回测完成率、策略对比使用率 |
| 金融质量指标 | 判断数据和分析是否可信 | 数据新鲜度、provider 可用率、数据缺失率、回测反偏差状态 |
| 交易安全指标 | 判断交易路径是否安全 | 风控拦截率、人工确认率、kill switch 状态、订单异常率 |
| 系统运行指标 | 判断系统是否稳定 | API 错误率、任务失败率、SSE 断连率、缓存命中率 |
| 审计完整性指标 | 判断关键动作是否可追溯 | 审计事件覆盖率、数据快照覆盖率、模型/prompt 记录率 |

## 2. 产品成功指标

| 指标 | 定义 | 目标口径 |
|---|---|---|
| 研究报告生成成功率 | 成功生成 AI/Web/Markdown/PPT 报告的次数 / 发起次数 | 应接近 100%，失败需有错误原因 |
| 回测完成率 | 成功产出 Backtest Result 的次数 / 发起次数 | 失败必须区分数据不足、参数错误、系统错误 |
| 策略优化有效率 | 有交易且通过基础质量门槛的优化结果 / 优化结果总数 | 无交易或数据不足不得排前 |
| Market Leaders 候选池可解释率 | 有入池/出池理由的候选股 / 候选池股票数 | 必须 100% |
| 报告可追溯率 | 带模型、prompt、数据快照、引用来源的报告 / 报告总数 | AI Research Center 目标为 100% |

## 3. 金融质量指标

| 指标 | 定义 | 归属模块 |
|---|---|---|
| 数据新鲜度 | 当前数据时间与市场时间的差距 | Data & Ops |
| provider 可用率 | provider 成功响应次数 / 请求次数 | Data & Ops |
| fallback 触发率 | fallback 次数 / provider 请求次数 | Data & Ops |
| 数据缺失率 | 缺失字段数 / 应有字段数 | Data & Ops |
| 回测数据假设完整率 | 显示复权、成本、滑点、成交约束、样本外状态的回测 / 回测总数 | Strategy Lab |
| 未来函数检查覆盖率 | 已执行未来函数/look-ahead 检查的策略 / 策略总数 | Strategy Lab |

## 4. 交易安全指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 风控拦截率 | 被 Risk Gate 拦截的订单 / 订单总数 | 用于监控风险，不直接追求越低越好 |
| 人工确认率 | 需要人工确认且已确认的订单 / 需要确认的订单 | managed/live-ready 必须 100% |
| 订单异常率 | 拒单、超时、状态不一致、券商回报异常 / 订单总数 | 必须可追踪原因 |
| reconciliation 差异数 | 本地订单/持仓与券商回报不一致的数量 | live-ready 前必须可检测 |
| kill switch 可用性 | kill switch 是否可见、可操作、可审计 | Trading 顶部状态必须显示 |

## 5. 系统运行指标

| 指标 | 定义 | 归属 |
|---|---|---|
| API 错误率 | 5xx + 业务错误 / API 请求总数 | API / Ops |
| 任务失败率 | failed task / task run 总数 | Ops |
| SSE 断连率 | SSE 异常断连次数 / SSE 会话数 | Ops |
| 缓存命中率 | cache hit / cache lookup | Data & Ops |
| DuckDB 查询失败率 | DuckDB 查询失败次数 / 查询总数 | Data & Ops |
| LLM 调用失败率 | LLM error / LLM run 总数 | AI Research |

## 6. 告警需求

| 告警级别 | 场景 | 处理动作 |
|---|---|---|
| P0 | kill switch 触发、订单状态不一致、真实执行回报异常 | 阻断后续交易，要求人工确认和系统维护处理 |
| P1 | provider 主源不可用、数据严重延迟、回测结果缺关键假设 | 降级或标红，不允许标记 live-ready |
| P2 | 单次 AI 生成失败、单次回测失败、缓存刷新失败 | 页面提示并记录任务失败 |
| P3 | 非关键页面数据为空、低优先级 provider 失败 | 记录日志，允许降级展示 |

## 7. Ops Dashboard 需求

Ops Dashboard 至少展示：

- 当前系统模式：research / paper / managed / live-ready。
- provider 健康：akshare、mootdx、tencent、cninfo、iwencai、qmt。
- 数据新鲜度：行情、财务、公告、新闻、研报。
- 任务状态：数据刷新、AI research、回测、报告生成、交易动作。
- 最近错误：错误类型、影响模块、处理建议。
- 审计摘要：最近人工确认、风控拒绝、订单动作、配置变更。

## 8. 验收要求

- Phase 31 必须开始记录数据质量指标。
- Phase 35 必须开始记录交易安全指标。
- Phase 37 必须形成统一 Task Run / Audit Event。
- Phase 38 必须在 WebUI 顶部或 Ops 页面展示关键运行状态。

## 9. 不做事项

- 不在文档阶段引入复杂监控系统选型。
- 不要求立即接 Prometheus、Grafana 或外部告警平台。
- 不把指标做成“装饰性数字”；没有采集来源的指标不得显示为真实值。
